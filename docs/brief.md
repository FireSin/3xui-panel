# Бриф: 3xui Panel

Мобильный Android-клиент для удалённого управления серверами 3x-ui (аналог функционала веб-панели) через собственный бэкенд.

## Сценарий использования

- Пользователь устанавливает Android-приложение.
- При первом запуске бэкенд выдаёт анонимный токен, привязанный к устройству.
- Пользователь добавляет одну или несколько панелей 3x-ui (URL + логин + пароль).
- Бэкенд сохраняет креды панелей (зашифрованно) и от имени пользователя обращается к 3x-ui API.
- Пользователь управляет инбаундами, клиентами, смотрит статистику и статус — всё через мобильный UI.

## Границы

- **Только админская функциональность панели.** Приложение не является VPN-клиентом и не подключается к Xray-core как пользователь.
- **Без разграничения ролей внутри панели.** Если пользователь добавил панель — у него полный доступ к её функционалу (как если бы он залогинился в веб-UI панели).
- **Мультитенантность на уровне приложения:** каждый пользователь (устройство/аккаунт) видит только свои панели; данные между пользователями изолированы.

## Архитектура

```
Android app  ──HTTPS──▶  Backend  ──HTTPS──▶  3x-ui panels
```

- Android общается только со своим бэкендом, прямого доступа к панелям из приложения нет.
- Бэкенд поддерживает HTTP-сессии с каждой панелью (login по cookie), кэширует/переиспользует их.
- Креды панелей шифруются на бэкенде (симметричное шифрование, ключ из конфига/secret manager).

## Стек

### Mobile
- Kotlin 2.x
- Jetpack Compose, Material 3
- Coroutines / Flow
- Hilt (DI)
- Retrofit + OkHttp + kotlinx.serialization
- DataStore (хранение токена, настроек)
- min SDK: обсудить на стадии архитектуры (ориентир — Android 8.0 / API 26)

### Backend
- Java 25 (LTS)
- Spring Boot 4.0.x
- Spring Web, Spring Security, Spring Data JPA, Spring WebFlux WebClient (для походов в 3x-ui)
- PostgreSQL 17
- Liquibase
- Docker / docker-compose для локальной разработки

### CI/CD
- GitHub Actions.
- Workflow на push в `main` и на git-тег `v*` — собирает release-APK, подписывает (keystore в секретах), публикует в GitHub Releases.

## MVP-фичи

1. **Мультипанель** — добавление нескольких панелей 3x-ui, переключение между ними в UI.
2. **Дашборд панели** — статус Xray, CPU / RAM / сеть, аптайм.
3. **Инбаунды** — список, создание, редактирование, удаление, включение/выключение.
4. **Клиенты** — добавление, редактирование, удаление клиентов в инбаунде; сброс трафика.
5. **Шаринг конфига клиента** — QR-код и подписочная ссылка для отправки конечному пользователю.
6. **Статистика трафика** — по клиентам и инбаундам, графики.

## Бэклог (после MVP)

- **Действия над сервером** — рестарт Xray, бэкап/восстановление конфигурации.
- **Push-уведомления** через FCM — алерты по лимитам трафика, истечению клиентов, недоступности панели. Бэкенд периодически поллит панели.
- **Привязка email** к анонимному аккаунту и синк данных между устройствами пользователя.
- **Двухфакторка** при привязке email.
- **Тарифы / монетизация** (если понадобится).

## Открытые вопросы

- Точная минимальная версия Android.
- Хостинг и деплой бэкенда (VPS / Docker / managed).
- Бюджет на инфраструктуру (влияет на выбор БД и мониторинга).
- Ключ шифрования кредов — где хранить (env / HashiCorp Vault / KMS).
- Стратегия ретраев и обработки ошибок при общении с панелями (таймауты, circuit breaker).
